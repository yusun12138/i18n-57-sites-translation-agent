# 文案系统 Headless API — Skills 接入指南

## 一、概述

文案系统（language-configuration-center）提供了一组 Headless API，供 AI Agent 通过 `arch-mcp-proxy` 调用，实现多语言 Key 的查询、产品列表获取和数据导出能力。

**网关名称**：`language-configuration-center`（正式）/ `language-configuration-center-gray`（灰度）

**接口路径前缀**：`/headless/api/v1`

**鉴权方式**：ULP Token（通过 Cookie 传递）

📄 [https://sdoc.sheingroup.net/docs/3077993681998239744?scode=UDepD30miZ0nCWK01my1bm00#7dc0a4fb-c0d4-4a6b-902d-373652abbcf5](https://sdoc.sheingroup.net/docs/3077993681998239744?scode=UDepD30miZ0nCWK01my1bm00#7dc0a4fb-c0d4-4a6b-902d-373652abbcf5)

## 四、测试环境调用方式

测试环境下，`{{ulp_token}}` 占位符获取的是**生产环境**的 kite token，无法在测试环境通过 ULP 校验。因此需要**手动从浏览器获取测试环境的** `ulp_token`。

### 4.1 获取测试环境 ulp_token

1. 在浏览器中打开文案系统测试环境页面（`https://language-config-center-api-test01.biz.sheincorp.cn/language-management/library`）并登录

2. 打开 Chrome DevTools（F12）→ Application → Cookies

3. 找到 `ulp_token` 字段，**完整**复制其值（token 很长，注意不要截断）

### FAQ

**Q: 不清楚怎么获取生产环境** `{{ulp_token}}`**？**

A：可以将这个文档📄 [Agent Skills(cc plugins)开发指南](https://sdoc.sheingroup.net/docs/3077993681998239744?scode=UDepD30miZ0nCWK01my1bm00#7dc0a4fb-c0d4-4a6b-902d-373652abbcf5)告诉AI，让他自己了解怎么获取

发请求 **→** mcp-proxy 拦截 **→** 发现 {{ulp_token}} 占位符  **→** 从你本地的 Kite 登录态中取出真实 token **→** 把 {{ulp_token}} 替换成真实 token **→**  带着真实 token 转发给后端网关

**Q: 为什么测试环境不能用** `{{ulp_token}}`**？**

A: `{{ulp_token}}` 是 mcp-proxy 从本地 kite 登录态获取的 token，对应的是**生产环境**的 ULP 系统。测试环境使用独立的 ULP 系统（`ulp-test01.sheincorp.cn`），两边 token 不通用。测试环境必须手动从浏览器 Cookie 复制 `ulp_token`。

**Q: 灰度环境调用返回「无法找到可用的服务实例」怎么办？**

A: 灰度实例可能注册在特定数据中心（如中央P2），而 MCP proxy 默认路由到其他 DC。需要：

1. 在 mesh 网关管理平台查看灰度实例所在的数据中心标签页（如「中央P2」）

2. 在请求 Header 中添加 `mcp-proxy-dc: central_p2_dc`（按实际 DC 填写）

**Q: Cookie key 用** `token` **还是** `ulp_token`**？**

A: **统一使用** `ulp_token`。使用 `token` 作为 Cookie key 会导致 ULP 系统无法正确解析 token，返回 `400106 token not valid`。

**Q: 灰度网关的 ULP 系统名应该绑定什么？**

A: 绑定与正式环境相同的 `language-center`，**不要**绑定 `language-center-gray`。灰度和正式共用同一个 ULP 系统，绑定错误的系统名会导致 token 校验失败。

**Q: 测试环境直连和 MCP Proxy 调用有什么区别？**

A: 直连方式直接访问测试环境服务地址（`https://language-config-center-api-test01.biz.sheincorp.cn/api/...`），不经过 mesh 网关，适合本地调试。MCP Proxy 方式经过网关代理，是 Skills 正式调用的方式，需要提前完成网关授权。

**Q: 导出任务返回 status=4（失败）怎么办？**

A: 可能原因：

3. 文件上传 OSS 失败

4. 导出数据量过大超时

5. 服务内部异常

建议缩小导出范围（通过 `projects`、`keyword` 等过滤条件）后重试。
